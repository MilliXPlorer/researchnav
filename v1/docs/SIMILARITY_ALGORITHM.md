# Similarity Algorithm

This document describes the TF-IDF/cosine implementation used by ResearchNAV.
The canonical weighted policy and API contract are documented in
`docs/SIMILARITY_SCORING.md`.

> The system should be able to identify duplicates through a TF-IDF algorithm
> based on the research title. Duplicates should be flagged and the instructor
> should see the similarity result as a percentage.

## Authoritative constants

| Constant                                    | Value                              | Location                                                                    | Purpose                                                              |
| ------------------------------------------- | ---------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `title_weight` / `content_weight`           | `0.30` / `0.70`                    | `backend/config/researchnav.php` versioned policy                           | Contributions to the authoritative weighted overall score.           |
| `moderate_threshold` / `high_threshold`     | `0.40` / `0.70`                    | `backend/config/researchnav.php` versioned policy                           | Backend-authoritative classification boundaries.                     |
| `title_alert_threshold`                     | `0.90`                             | `backend/config/researchnav.php` versioned policy                           | Near-exact-title safeguard requiring adviser review.                 |
| `MAX_CANDIDATES`                            | `250`                              | `similarity/cli.py`                                                         | Upper bound of trusted candidates sent to the Python worker per run. |
| `MAX_INPUT_BYTES` / `MAX_TITLE_LENGTH`      | `262144` / `500`                   | `similarity/cli.py`                                                         | Worker protocol limits.                                              |
| `SimilarityResult::FLAG_THRESHOLD` DB check | `final_similarity_score` in `0..1` | `database/migrations/2026_07_13_000000_create_similarity_results_table.php` | Persistence invariant.                                               |

Every score is normalized to `[0, 1]` and exchanged at 12-decimal fixed-point
precision. Percentages are generated by Laravel and displayed to users at two
decimal places.

## Official method: separate title and content TF-IDF + cosine

The official similarity basis is term frequency-inverse document frequency
(TF-IDF) vectors compared with cosine similarity.

1. The researcher submits a title (and an optional abstract).
2. If a submission is approved, its status changes to `archived`, the archive
   status to `archived`, and visibility to `public`. Only those trusted records
   are ever compared against.
3. The researcher requests a check (`POST /api/research/{id}/similarity/check`)
   with an empty JSON body; only the submitter or an authorized reviewer of the
   source document may do so.
4. The PHP side builds the candidate set from public, archived documents
   (`submission_status = archived`, `archive_status = archived`,
   `visibility = public`) whose `deleted_at` is null, ordered by id.
   Soft-deleted records are never scored or trusted. Identical titles are not
   excluded at query time; an exact duplicate simply receives a cosine of
   `1.000000` and is flagged.
5. The candidate list is capped at `MAX_CANDIDATES` and passed to the Python
   worker over a versioned JSON protocol.
6. The worker preprocesses each title deterministically: `casefold()` plus a
   Unicode word-boundary token regex (`\w\d{2,}`), removing a versioned stopword
   list stored in `similarity/stopwords.py`. No NLTK corpus download is needed.
7. `TfidfVectorizer` (analyzer = the same preprocessing, `norm=None`) builds an
   unnormalized sparse matrix; the empty-vocabulary case produces a valid
   zero-column matrix instead of an error.
8. Cosine scores between the source row and every candidate row are computed in
   `similarity/cosine.py` and normalized to `[0, 1]`.
9. Laravel calculates the final normalized score as
   `(title cosine * 0.30) + (content cosine * 0.70)`, retaining both product
   precisions until one final 12-place truncation. Results are ranked by
   that score descending, with the candidate id as a deterministic tiebreaker.
10. Each result is persisted with `source_research_id`, `matched_research_id`,
    both comparison scores, the final score, matched terms (up to 32), and a
    contextual analysis note. Laravel derives classification, the 70% overall
    flag, the 90% title alert, and adviser-review status.

The check is rate-limited to two runs per user per source and two runs per
user per minute, and the researcher can run it only on their own documents.

## FastText: supporting evidence only

A FastText sentence-vector cosine may be attached to results, but it **never**
contributes to the weighted score, classification, flags, or ranking:

- If a model is available, `fasttext_similarity.py` computes a supporting
  semantic match (`fasttext_score` / `fasttext_support_score`).
- If the model/package is missing or faults at runtime, both paths emit `null`
  support scores and sanitized contextual copy; TF-IDF cosine scoring continues
  unaffected.

The public repository endpoint (`POST /api/repository/similarity`, limited to
two calls per minute and 20 per hour per IP) uses the same preprocessing and
TF-IDF cosine on an unpersisted query string. It builds separate query-to-title
and query-to-ready-manuscript-content vectors and applies the same 30/70
weighted formula. If content is unavailable, it returns a title score but no
official overall score or classification.
FastText support is supporting-only and never changes any of these scores or
their ranking; a missing package/model returns null support. Repository browsing (`GET
/api/repository`, 60 per minute per IP) does not trigger similarity work.

## Edge cases covered by tests

- Punctuation-only and stopword-only titles produce zero lexical scores
  without crashing (empty-vocabulary matrix path).
- Non-ASCII titles compare on their Unicode tokens (`Café` ≠ `cafe` is not
  assumed; `casefold()` preserves diacritics).
- Empty candidate sets return empty results on both the internal and public
  paths.
- Soft-deleted public candidates are excluded from trusted scoring
  (`backend/tests/Feature/SimilarityCheckTest.php`).
- FastText runtime faults are nulled and never change ranking.
- Scores are bounded to `[0, 1]`; malformed and non-finite values are rejected.

## Separate feature: manuscript-content retrieval

`GET /api/repository?q=` is retrieval, not plagiarism detection and not the
title-similarity algorithm above. It searches title, abstract, keywords, and
authors, plus ready extracted manuscript bodies, but returns metadata only: no
snippets, scores, or body text. Only non-deleted records with
`archive_status = archived`, `visibility = public`, and `submission_status` of
`approved` or `archived` qualify.

MariaDB uses the private `manuscript_search_documents.body_text` FULLTEXT index
with natural-language mode for BM25-family relevance ordering. SQLite uses a
LIKE fallback and therefore has different ranking behavior. The latest current
`final_manuscript` is authoritative; a canonical import is used only as a
cryptographically and path-verified fallback. PDF and DOCX are supported. DOC
is unsupported, and scanned/OCR-dependent PDFs produce no extractable text.

The projection stores private derived `LONGTEXT`, never a public body or
snippet. Extraction runs through a bounded JSON process boundary using the
configured Python executable. `MANUSCRIPT_SEARCH_PYTHON_BINARY`,
`MANUSCRIPT_SEARCH_CLI_PATH`, timeout and size limits, and extractor version
are documented in `backend/.env.example`. A fixed executable and OS/container
parser isolation are recommended. Term probing remains possible because query
results can reveal whether a public indexed term is present.

The migration must be applied before the initial
`php artisan repository:reindex-manuscripts` backfill. Failed, unsupported,
no-source, and no-text outcomes remain operational projection statuses; failed
reindexing clears stale body text while metadata search continues. The
scheduled retry runs every ten minutes, and production must invoke
`php artisan schedule:run` every minute. SQLite feature tests do not validate
MariaDB FULLTEXT; live MariaDB validation is required before deployment.

Similarity requests consume only trusted current candidate projections and
never invoke candidate retry/reindex work. A trusted projection is `ready`, has
a nonblank body, a lowercase 64-character hexadecimal source SHA-256, and an
`extractor_version` exactly equal to the configured current version. They
snapshot/revalidate candidate titles and projection identity/status/source/body
hashes/version before persistence or a public response. Persisted checks also
snapshot the source mode (trusted projection, selected file, or unavailable)
and selected-file identity/hash, so an unavailable source gaining content
cannot produce a mixed result.
